# 압축·전달 실측 (2026-09-01 · 리더 · sharp 8.18.3 + Next 옵티마이저)

## ⛔ 먼저 — 8/28 값을 «복사하면» 틀린다

| | 8/28 | **9/4 실측** |
|---|---|---|
| 이미지 슬롯 최대 | `sizes` 에 **832px** | ★ **624px** (패널 672 − `p-8` 24×2) |
| 루트 폰트 | — | **12px** (`html{font-size:75%}`) |

★ `--container-page: 60rem` = **720px** 이다. CSS 주석의 *「960px」* 는 **16px 가정이라 낡았다**(별건).
→ ⛔ ~~`sizes="(min-width: 768px) 624px, 100vw"`~~ **[정정 2026-09-01 · QA §72-1 · 리더 스펙 오류]**

★★ **모바일 항 `100vw` 가 틀렸다. 실제 슬롯은 `100vw − 54px` 다**(페이지 패딩 24 + 패널 패딩 30).
```
390 뷰포트 · dpr 3    선언 100vw → 390×3 = 1170 → deviceSizes 다음값 w=1200
                     참값  336  → 336×3 = 1008 → w=1080
대가: 지도 178.7→203.2 · 로드뷰 166.4→201.6 = 첫 방문 391.4 → 451.1 KB (+61.1 · +15.7%)
```
**확정**: **`sizes="(min-width: 768px) 624px, calc(100vw - 54px)"`**
슬롯 모델 `100vw − 54px` 이 **3폭 전부 실측 일치**(320→266 · 360→306 · 390→336).
⚠ 320 은 `w=828` 로 더 내려간다(273.3 KB).

★ **내 «예보»는 틀리지 않았다** — `w=1080` 값(178·166)은 QA 실측과 **완전 일치**했다.
틀린 것은 **«어느 `w` 가 선택되는가»** 이고, 그것은 **`sizes` 가 정한다.**
⚠⚠ **이것이 «구현 이탈»이 아니라 «스펙 오류»다** — 개발자는 내 스펙대로 넣었다. **귀속을 갈라 적는다.**

⛔ 그리고 **8/28 의 `832px` 는 여전히 쓰지 마라**(슬롯 624).

## ⛔ `quality` 는 `[75, 90]` 만 허용된다 (`next.config.ts`)
목록 밖 값(예: 92)을 쓰면 옵티마이저가 **400** 을 내고 `next/image` 가 **조용히 75 로 떨어진다.**
8/28 이 실제로 그 상태였다(선언 90 · 실제 75). **q=90 을 쓴다. 92 를 쓰지 마라.**

## ⛔ `w` 는 `deviceSizes` 목록만 유효하다
실측: `w=1280` → **400**. 유효값은 `640 · 750 · 828 · 1080 · 1200 · 1920 · …`
→ **모바일(390뷰포트 · 슬롯 336css · dpr3 → 1008)** 은 **`w=1080`** 을 받는다. **그것이 검증 대상이다.**

## 실측표 — 조합원이 «실제로» 받는 바이트

| 이미지 | 소스 | 모바일 `w=1080` WebP | 판정 |
|---|---|---|---|
| **배치도** | 무손실 재압축 PNG **46KB**(원본 66KB) | WebP **98KB** | ★ **`unoptimized` PNG** — WebP 보다 **작고** 무손실 |
| **지도** | 무손실 재압축 PNG **898KB**(원본 1056KB) | WebP **178KB** | **최적화 · `quality={90}`** |
| **로드뷰** | 1600폭 JPEG q90 4:4:4 **456KB**(원본 3936KB) | WebP **166KB** | **최적화 · `quality={90}`** |

**모바일 실수령 합계 ≈ 390KB**(배치도는 소스 46KB 그대로 나간다).

## 검산 — «무손실»을 값으로 확인했다
`sharp(...).png({compressionLevel:9, palette:false})` 산출물이 **원본과 픽셀 동일**함을 raw 버퍼 비교로 확인:
**배치도 동일 ⭕ · 지도 동일 ⭕.** ⚠ 8/28 주석대로 **`effort:10` 은 팔레트 경로를 켜 조용히 손실이 된다. 쓰지 마라.**

## 판독 대상 생존 확인 — ★ **소스가 아니라 «Next 산출물»에서 확인했다**

⚠⚠ 처음에 **내 JPEG 후보**에서 확인할 뻔했다. **조합원이 받는 것은 그 파일이 아니라 Next 의 WebP** 다.
**엉뚱한 산출물을 검증할 뻔한 것**이고, `union-qa-testing` 의 «대상» 축 오류와 같은 계보다.

- **지도 `w=1080`**: `천막 및 집회: 코리아나호텔(폴바셋) 앞` ⭕ · **`화장실 : 임시화장실 및 인근화장실(시청역, 스벅 등) 이용`** ⭕ ·
  `무대 1`~`무대4` ⭕ · `임시화장실` 2곳 ⭕ · `광화문역`·`시청역` ⭕
- **로드뷰 `w=1080`**: `코스콤 지부 구 역` ⭕ · 미니맵 `코스콤`·`코리아나호텔` ⭕ · `PAUL BASSET` 간판 ⭕(약간 뭉갬) ·
  `청계광장 교차로` ⭕ · ⚠ **`2026년 04월(최신)` 은 판독 경계** — 필수 대상은 아니다(거리뷰 시트가 촬영월을 따로 준다)
- **배치도**: 무손실이라 **판독 검사 불필요**. ⚠ 다만 **733px 원본을 336css 에 넣으면 지부명이 작다** —
  ★ **8/28 이 같은 상태를 «게시 블로커가 아니다»로 판정했다**(핀치 확대가 원본에 닿는 것이 근거이고,

## 반례 하나 — 기록해 둔다
**「줄이면 작아진다」가 PNG 에서 틀렸다**: 지도를 1300 → 1248 로 줄였더니 **898KB → 1109KB 로 «커졌다».**
