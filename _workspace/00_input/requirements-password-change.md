# 요구사항 — 관리자 비밀번호 변경 기능 (2026-08-17)

## 사용자 요청 원문

> 관리자모드 진입 시 비밀번호 변경기능 추가

## 배경

관리자 초기 비밀번호는 서버 배포 시 생성되어 `/root/koscomlabor-api/ADMIN_PASSWORD.initial`
에 기록되었고, 변경하려면 `scripts/hash-password.mjs`로 해시를 만들어 `.env`의
`ADMIN_PASSWORD_HASH`를 교체하고 컨테이너를 재기동해야 한다. 관리자(노조 담당자)가
직접 수행하기 어려운 절차이므로, 관리 화면에서 비밀번호를 바꿀 수 있어야 한다.

## 리더 확정 사항 (사용자 확인 완료)

1. **저장 위치: DB로 이전.** 현재 `ADMIN_PASSWORD_HASH`는 부팅 시 1회만 읽히므로
   런타임 변경이 불가능하다. `admin_credentials` 단일 행 테이블을 신설하고, env 값은
   **최초 부팅 시드**로만 사용한다 (행이 없을 때만 INSERT). 이후 DB 행이 권위 값이다.
2. **초기 비밀번호 처리: 경고 배너 + 변경 유도.** 강제 차단하지 않는다. 아직 시드
   해시(= 한 번도 변경한 적 없음)를 쓰고 있으면 관리 화면 상단에 경고 배너와
   변경 CTA를 항상 표시한다.
3. **배포: 프로덕션까지 진행.** 프로덕션 DB 마이그레이션 + API 컨테이너 재빌드/재기동
   + 웹 배포까지 이번 작업 범위에 포함한다.

## 기능 요건

- 관리 화면(로그인 후)에서 "비밀번호 변경" 진입 가능
- 입력: 현재 비밀번호 / 새 비밀번호 / 새 비밀번호 확인
- **현재 비밀번호 재확인 필수** (세션 쿠키만으로 변경 불가 — 자리 비운 브라우저 탈취 방어)
- 새 비밀번호 규칙: 12자 이상 200자 이하, 현재 비밀번호와 달라야 함
  (12자 하한은 기존 `scripts/hash-password.mjs`와 일치시킨다)
- 변경 성공 시: **현재 세션을 제외한 모든 세션 무효화** (다른 기기 로그인 해제)
- 정적 Bearer 토큰(`ADMIN_API_TOKEN`)은 이 변경의 영향을 받지 않는다 (복구 수단 유지)
- 비밀번호 분실 복구 경로: 서버에서 실행하는 운영 스크립트로 DB 해시를 직접 교체
  (`server/scripts/set-password.mjs` 신설). 절차는 07 문서에 기록

## 비기능 요건

- 무차별 대입 방어: 현재 비밀번호 오입력은 로그인 rate limit 버킷에 카운트
- 평문 비밀번호는 로그·에러 메시지·DB 어디에도 남기지 않는다
- 에러 응답 형식은 기존 `{ error: { code, message } }` 유지
- 접근성: 라벨 연결, `autoComplete` 적절 지정, 에러 `role="alert"`, 대비 기준 준수
- 기존 06 API 명세 / 07 배포 문서는 **이어서 갱신**한다 (아카이브 이동 금지 —
  소스 주석이 `_workspace/06_backend_api_spec.md`를 계약 출처로 참조하고 있음)
