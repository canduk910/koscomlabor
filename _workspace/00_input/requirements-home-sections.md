# 요구사항 — 메인페이지 탭 → 섹션 나열 전환 (2026-08-17)

## 사용자 요청 원문

> 메인페이지에서 탭방식이 아니라 섹션나열방식으로 변경하고 싶어.
> 공지사항, 금융노조 소식, 노동교육, 방명록

## 발단 — 이 요청이 나온 맥락

사용자 신고: "관리자페이지에서 글을 등록했는데, 메인페이지에서 글이 보이질 않아."

리더 조사 결과 **데이터·API·배포는 전부 정상**이었다. 등록된 글(금융노조 소식, kfiu.org
링크형)은 메인페이지 HTML 에 실제로 렌더되어 있었고, `id="panel-news"` 패널이
`hidden` 이라 보이지 않았을 뿐이다. 원인은 `BoardTabs` 의 기본 탭이 공지사항 고정
(`DEFAULT_TAB = "notices"`)인데 공지사항이 0건이어서, **사이트의 유일한 콘텐츠가
빈 탭 뒤에 가려진 것**이다. 첫 방문 조합원은 "등록된 공지사항이 없습니다"만 본다.

즉 이번 전환은 스타일 변경이 아니라 **실제로 발생한 정보 은폐 문제의 구조적 해결**이다.
섹션 나열로 바꾸면 기본 탭 개념 자체가 사라져 같은 문제가 재발할 수 없다.

   ① 공지사항 ② 금융노조 소식 ③ 노동교육 ④ 방명록
2. **노출 건수: 전체 노출.** 섹션당 개수 제한·더보기 없음. 별도 목록 페이지가 없고
   현재 게시물 수가 적어 가장 단순하다. 게시물이 쌓이면 그때 더보기를 도입한다
3. ~~**노동교육: 정적 외부 링크 모음.** 게시물 분류(DB category)가 아니다.~~
   → **개정 (같은 날, 사용자 추가 요청으로 번복). 아래 참조.**

## 노동교육 요건 개정 (2026-08-17, 사용자 추가 요청)

> 사용자: "게시물을 수정가능한 형태로 하면 나중에 수정할게"

노동교육 링크를 **관리자 화면에서 등록·수정·삭제**할 수 있어야 한다. 따라서 정적 상수
배열 방식을 폐기하고, **공지사항·금융노조 소식과 나란한 세 번째 게시물 분류**로 만든다.

**채택 근거:** 기존 posts 파이프라인이 이미 필요한 것을 전부 갖고 있다 — 링크형 타입,
제목·URL·출처, 게시일 정렬, admin CRUD, soft delete. 별도 `education_links` 테이블을
새로 만드는 것은 같은 기능의 중복 구현이다.

**전 계층 영향:**

| 계층 | 변경 |
|------|------|
| DB | `posts.category` CHECK 제약에 `'education'` 추가 (신규 마이그레이션) |
| 서버 | `postValidate.ts`, `routes/posts.ts`(공개 목록 category 검증), `routes/admin.ts`(admin 목록 category 검증) |
| 프론트 타입 | `PostCategory = "notice" | "news" | "education"` + 파서 |
| 라우트 | `/education/[id]` 상세 페이지 신설 (작성형 대비), `ROUTES.education(id)` |
| admin | `PostForm` 분류 선택지에 "노동교육" 추가 |
| 메인 | 노동교육 섹션은 정적 카드가 아니라 **`PostList` 재사용** (kind 하나 추가) |
| 배포 | 프로덕션 DB 마이그레이션 필요 |

**하위 호환:** `'education'` 은 기존 값에 **추가**만 하므로 기존 공지·소식 데이터와
구버전 클라이언트에 영향이 없다.

## 노동교육 콘텐츠 (사용자 제공 — 검증 중)

원문은 `_workspace/00_input/content-education-links.md`. YouTube 링크 5건.
fact-verifier 1차 게이트 진행 중이며, **승인된 건만** 초기 데이터로 등록한다.
등록 후에는 사용자가 admin 에서 직접 수정한다.

## 기능 요건

- 4개 섹션을 세로로 나열. 각 섹션은 `<section>` + `<h2>` 제목
- 각 섹션에 앵커 id 부여 (`#notices`, `#news`, `#education`, `#guestbook`) —
  상세 페이지 "목록으로" 링크와 외부 공유용
- 기존 탭 인프라 제거: `BoardTabs.tsx`, `TAB_IDS`/`TabId`/`isTabId`/`TAB_QUERY_PARAM`,
  `ROUTES.homeTab`. 대체 상수(`ROUTES.homeSection` 등)를 routes.ts 에 정의한다
  (경로 하드코딩 금지 규칙 유지)
- `/notices/[id]`·`/news/[id]` 의 `backHref` 를 해당 섹션 앵커로 갱신
- 공지사항·금융노조 소식은 기존 `PostList` 를 그대로 재사용 (빈 상태 문구 포함)
- 방명록은 기존 `GuestbookPanel` 을 섹션 안으로 이동
- 히어로 패널·마감 스트립·온누리 가이드 카드는 유지 (배치는 디자이너 판단)

## 비기능 요건

  **섹션 바로가기(인페이지 내비게이션) 필요 여부를 디자이너가 판단**하고 근거를 남길 것
