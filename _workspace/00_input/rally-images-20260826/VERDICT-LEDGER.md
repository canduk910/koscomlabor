# ★ 후속 이월 후보 — 추가분 (2026-08-26 라운드 2)

## 7. «같은 정의로 다른 값»이 아니라 **«다른 정의를 같은 이름으로 부른 것»**

디자이너와 QA 가 **`min-content`** 라는 같은 이름으로 **다른 양**을 재고 있었다.

| | 정의 | 산문 ④ 구 문면 `keep-all` → `+break-word` |
|---|------|---|
| **A (디자이너)** | **`width:0` 요소의 `scrollWidth`** | **311 → 31** |
| **B (QA 초판 경고)** | `width:min-content` 요소의 rect | 311.1 → **311.1** |
| **C (참값)** | 고정폭 201px 박스의 초과 | 110px → **0** |

**A 가 옳다.** 근거:
- `break-keep` **단독 열에서는 A 와 B 가 같다**(311↔311.1 · 233↔233.4 · 165↔164.7) — 반올림 차이뿐이다.
  **`+break-words` 열에서만 갈린다.**
- A 는 **실제 렌더 가능한 최소 폭**, B 는 **CSS 내재 크기**다. 명세상 `overflow-wrap: break-word` 는
  내재 크기에 영향을 주지 않으므로 **B 는 «스펙상 맞는 값»이지만 «질문에 대한 답»이 아니다.**
- **참값 C 와 부호가 맞는 것은 A 다.** B 로 판정하면 **`break-words` 가 걸려 있어도 «넘친다»는 거짓 실패**가 난다.

→ **QA 부록 B-3 의 «min-content 로 재지 마라» 는 «`width:min-content` 로 재지 마라» 로 좁혀 읽어야 한다.**
   **`width:0` 의 `scrollWidth` 는 오히려 표준으로 써야 한다.**

### ★ 왜 이것이 §5.5 와 결이 다른가 — 하네스에 올릴 값이 있다

§5.5 는 **«같은 정의로 다른 값»**(스크롤바 오염 · 81.5% vs 85.4%)에서 나왔다.
이번은 **«다른 정의를 같은 이름으로 불렀다»** 다. 두 사람 다 자기 측정은 정확했고 **이름만 겹쳤다.**

→ 규율 후보: **측정값을 보고할 때 «무엇을 쟀나»가 아니라 «어떻게 쟀나»를 함께 적는다.**
   `min-content` · `표시 폭` · `슬롯` 같은 낱말은 **구현이 여럿**이다.
   디자이너가 §38.3 에 *"`scrollWidth`(width:0 상태의 min-content)"* 라고 **방법을 괄호로 적어 둔 덕에** 닫혔다.

## 11. ★ **맞는 숫자로 틀린 판정** — 문면 폭만 재고 «앉을 슬롯»을 확인하지 않았다

이 페이지는 **같은 뷰포트에서 슬롯이 두 가지**다. 차이는 카드 `p-5` 양쪽 = **80px**(200% 기준).

| 자리 | 360·sb0 | **360·sb15** | 320·sb15 |
|------|--------|------------|---------|
| **카드 안**(`rounded-panel … p-5`) | 216 | **201** | **161** |
| **카드 밖**(컨테이너 `px-4` 만) | 296 | **281** | **241** |

실측: **블록 2 = 카드 안**(201) · **QR 출석체크 섹션 = 카드 «밖»**(281).
`page.tsx` 의 `rounded-panel` 은 **두 곳뿐**이고 QR 섹션에는 없다.

### 무슨 일이 났나

QA 사전 실측표(부록 B-1)가 **카드 «안» 슬롯만으로** 작성됐는데 **어느 슬롯 기준인지 표에 안 적혔다.**
그 표에서 상품권 문장이 *"161(320급)에서 4px 초과"* 로 나왔고, **개발자가 그 수치를 주석에 인용**했다.
그런데 그 문장이 실제로 앉은 자리는 **카드 밖(281/241)** 이라 **전 구간 초과 0** 이다.

→ **클래스(`break-keep break-words`)는 그대로 둬도 된다**(비용 0). **다만 주석의 근거를 고쳐야 한다** —
   *"넘치니까"* → *"비용 0 인 보험"*. 안 고치면 **다음 사람이 «넘치던 줄»로 읽고 자리를 옮길 때 틀린 판단**을 한다.

### 규율 후보

> **문면의 폭만 재고 «그 문면이 앉을 슬롯»을 확인하지 않으면, 맞는 숫자로 틀린 판정을 한다.**
> 구현 전 사전 실측은 **자리가 미정이라 슬롯도 미정**이다.
> → **후보 슬롯을 전부 재거나, «어느 슬롯 기준인지»를 표에 명시**해야 한다.

★ **§7(«다른 정의를 같은 이름으로»)과 짝을 이룬다.** 둘 다 **측정값 자체는 정확했는데 맥락이 빠져 오독**된 경우다.
   §7 은 **«어떻게 쟀나»**, §11 은 **«어디를 기준으로 쟀나»** 가 빠졌다.
   → 합치면: **측정값은 «값 + 방법 + 기준»이 한 벌이어야 한다.** 셋 중 하나라도 빠지면 인용이 어긋난다.

## 12. ⛔ **`npm run start` 는 `EADDRINUSE` 에도 종료코드 0 을 낸다** — 리더가 직접 걸렸다

**리더가 이 라운드 내내 다른 사람에게 경고하던 함정에 스스로 걸렸다.**

경위:
1. 1차 재빌드 후 서버를 띄웠다(PID 78347) — **그것을 정지하지 않았다**
2. 2차 재빌드 후 `npm run start` 를 다시 띄웠다 → **`EADDRINUSE` 로 즉시 죽었다**
3. ★ **그런데 종료코드가 `0` 이었다.** 실패 신호가 없었다
4. `curl` 이 성공했다 — **낡은 서버(78347)가 응답했기 때문**이다
5. 문면 대조에서 **구 문면이 렌더에 나왔다**(`투쟁조끼` 6회 · 구 캡션 2회 · 구 산문 ④ 2회)

**BUILD_ID 대조로는 안 잡힌다** — 디스크의 `BUILD_ID` 는 새 값이었다. 낡은 «프로세스»가 문제였지 낡은 «파일»이 아니다.

### 규율

> **`npm run start` 뒤에는 «내가 띄운 프로세스가 그 포트를 잡았는지»를 확인한다.**
> - `lsof -nP -iTCP:3000 -sTCP:LISTEN` 로 **PID 를 읽고 기동 전후로 달라졌는지** 본다
> - 기동 로그에 **`EADDRINUSE` 가 0건**인지 확인한다
> - **종료코드 0 을 «성공»으로 읽지 마라** — 이 명령은 실패해도 0 을 낸다
> - **띄우기 전에 포트가 비었는지 먼저 확인**하고, 안 비었으면 정지 후 **해제를 확인**하고 띄운다

★ **§5.5 의 «구 서버 + 신 자산» 항목을 이 경로로 확장해야 한다.** 종전 기록은 *"어제 서버가 살아 있었다"* 였는데,
   **이번은 «내가 방금 띄웠다고 믿은 서버가 실은 안 떴다»** 다. **믿음의 출처가 다르다.**

## 13. 문안 계수 함정 2건 — 최종 게이트에서 실제로 걸렸다

### ① RSC 플라이트 페이로드가 같은 문자열을 두 번 세게 만든다

첫 계수에서 확정 문면 **E~L 이 전부 «2회»** 로 나왔다. **태그만 제거하면 `<script>` «내용»이 남는다** —
Next 의 RSC 플라이트 페이로드에 같은 문자열이 한 벌 더 들어 있다.
→ **`<script>…</script>` 를 먼저 통째로 지워야 한다.** 제거 후 본문 2,690자에서 각 **1회**.

★ 이것은 **`grep -c` 금지**(미니파이 산출물은 한 줄이라 무엇을 세든 1)와 **같은 계보**다:
**«세는 대상이 질문에 안 맞는다».** 이 프로젝트에서 세 번째다(`grep -c` · `min-content` 정의 · 이번).

### ② 짧은 문면은 **개수로 판정할 수 없다** — 부분문자열이기 때문

`배치도`(3자)는 **`금융노조지부배치도`·`주최측 배치도` 의 부분문자열**이다.
→ 개수 대신 **`<figcaption>` 값 완전일치**로 판정했다(각 1건).

★ **사용자 지시로 문면이 짧아지면 계수 방법도 함께 바뀌어야 한다.** 22자였을 때는 개수로 충분했다.

## 14. 오탐 예측이 **거짓 실패 5건**을 막았다

검증자가 게이트 «전»에 갈라 둔 오탐 목록이 그대로 맞았다:

| 문자열 | 기대 | 실제 | 정당 출현 |
|--------|------|------|-----------|
| `주최측 배치도`(괄호 없이) | 1 | **1** | 지도 범례 ③ 행(`rallyMap.ts`) |
| `여의도공원 쪽` | 2 | **2** | 산문 ② · 지도 대체면 |
| `여의도공원 방향` | 1 | **1** | 블록 1 `<dl>` — 원문 축자 |
| `인증샷` | 1 | **1** | QR `alt` 안 주최측 문안 전사 |
| `상품권 5만원` | 1 | **1** | 확정 문면의 일부(금지 대상 아님) |

**리더가 이 다섯을 «사라져야 하는 것»에 넣을 뻔했다.** 그대로 갔으면 **실패 5건이 나고 개발자가 정상 코드를 되돌렸을 것**이다.
→ 규율: **«0건이어야 한다» 목록을 만들 때, 각 문자열의 «정당한 출현처»를 먼저 세라.**

## 15. ★ **텍스트 좌표로 자르지 마라 — 구조(태그)로 잘라라**

QA 1회차가 블록 2 의 `※` 개수를 **텍스트 좌표로 슬라이스**해 셌다.
**배너가 생기면서 경계 문자열 `QR 출석체크` 가 배너 문장에 «먼저» 등장**해
슬라이스가 빈 문자열이 됐고 → **«블록 2 ※ = 0» 이라는 거짓 값**이 나왔다.
`<section>` 태그 경계로 다시 세어 **1** 을 얻고 AX 트리로 교차 확인했다.

> **텍스트 좌표로 자르는 방법은 새 콘텐츠가 들어오면 «조용히» 깨진다.**
> 오류가 아니라 **그럴듯한 숫자**가 나오기 때문에 더 위험하다.

★ 이 라운드에서 **«세는 방법이 질문에 안 맞는다»가 다섯 번**이었다:
`grep -c`(미니파이 한 줄) · `min-content` 정의 · 슬롯 기준 · RSC 플라이트 페이로드 · **이 건**.
→ **하나의 규율로 묶는다: «무엇을 세는가»보다 «어떻게·어디를 기준으로 세는가»가 자주 틀린다.
   계수 결과가 예상과 다르면 «값»을 의심하기 전에 «경계»를 의심하라.**
