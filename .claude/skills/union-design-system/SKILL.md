# Union Design System — 시각적 명쾌함 설계 기준

전 연령대 조합원이 중요 정보를 한눈에 오독 없이 파악하게 하는 디자인 기준. 핵심 수단은 두 가지다: **크기 대비**(타이포그래피 위계)와 **색상 대비**(명도 차이).

## 0. 모던 스타일 기준 (v3 — toss.im 계열 지향, 사용자 지정)

사용자는 시스템 폰트 폴백과 밋밋한 레이아웃을 "구식·촌스럽다"고 평가했고, 이후 **`toss.im` 을 이상향으로 지정**하며 디자인 전격 교체를 요청했다. 다음이 이 프로젝트의 기본 스타일 언어다.

### 0.1 기준 레퍼런스와 그 한계

**`toss.im` 의 디자인 언어를 가져온다. 자산·브랜드는 가져오지 않는다.** 로고·일러스트·마스코트·전용 서체(Toss Product Sans 등)·특유의 브랜드 컬러를 복제하지 마라 — 상표 문제이고, 노조 공식 채널이 핀테크 기업으로 오인될 이유가 없다. 가져오는 것은 **공간·타이포·표면·모션의 운용 방식**이다.

### 0.2 모던함을 만드는 6가지 (구체 수단)

1. **여백이 주역이다.** 요소를 늘리지 말고 숨 쉬게 둔다. 대섹션 간 수직 간격은 모바일 64~80px / 데스크톱 120~160px 급으로 크게. 섹션 위 여백은 아래 여백의 2배 이상(§1 규칙 계승). 여백이 부족한 화면은 어떤 색·라운드를 써도 구식으로 보인다
2. **한 화면에 하나의 메시지.** 헤드라인은 크고 굵고 **짧게**. 대형 한글 타이포는 자간 음수(-0.02em~-0.01em), 행간 1.15~1.3
3. **표면 최소주의.** 배경은 흰색과 아주 연한 회색 2단계로 충분하다. **구분은 테두리보다 여백과 미묘한 그림자로.** 테두리 남용이 구식 인상의 가장 흔한 원인이다. 카드에 테두리+그림자+배경색을 동시에 주지 마라 — 하나를 골라라
4. **라운드를 크게, 일관되게.** radius 스케일 12/16/24/32px. 버튼은 full-round 또는 12~16px 중 하나로 통일. 카드는 라운드가 기본
5. **강조는 아껴서 한 곳에.** 주색은 넓게 바르는 색이 아니라 **시선을 모으는 색**이다. 한 화면에 주색 강조 면은 1~2개
6. **모션은 미묘하고 빠르게.** 150~250ms, ease-out, `transform`/`opacity` 만 사용(레이아웃 속성 애니메이션 금지). **`prefers-reduced-motion: reduce` 대응 필수.** 등장 애니메이션으로 콘텐츠를 지연 노출시키지 마라(§0.4 위반)

### 0.3 노조 페이지의 제약 — 모던함이 양보해야 하는 선

`toss.im` 을 그대로 따르면 **이 프로젝트에서 깨지는 것들**이 있다. 아래가 우선한다:

- **연한 회색 텍스트 금지.** toss 계열은 저대비 회색을 즐겨 쓰지만, 조합원 연령대가 넓다. 본문 7:1(AAA) 목표와 보조 텍스트 `#595959` 하한(§2)은 **모던함보다 우선한다.** "세련돼 보여서" 대비를 낮추는 선택은 반려 사유다
- **정체성 색은 유지한다** (사용자 확정). 금융노조 딥블루 계열을 주색으로 쓴다. 코스콤 오렌지는 회사 CI 맥락에 한정하고 노조 사업에 확장하지 않는다
- **공식성을 잃지 않는다.** 노조 공식 채널이다. 이모지 남발·과한 구어체 마이크로카피·제품 마케팅 어투를 쓰지 마라. 친근함은 **레이아웃과 여백**으로 만들고, 신뢰는 **정확한 문구·게시일·출처 표기**로 만든다
- **폰트: Pretendard Variable 셀프호스팅 필수.** 한글 사이트에서 시스템 폰트 폴백은 즉시 구식 인상을 준다. 외부 CDN 금지. 웨이트 400/600/700/800 운용
- **금지**: 빨강 아웃라인 타이포(웹 가독 저하), 대비 미달 조합의 "세련미" 목적 사용

### 0.4 콘텐츠 은폐 금지 — 모던 UI 패턴의 함정 (실제 사고 기록)

**이 프로젝트에서 실제로 사고가 났다.** 메인페이지가 탭 방식이었고 기본 탭이 공지사항 고정인데 공지가 0건이어서, **사이트의 유일한 콘텐츠가 `hidden` 패널 뒤에 완전히 가려졌다.** 관리자는 글을 올렸는데 조합원은 빈 화면을 봤다. 원인 분석·전환 기록은 `_workspace/02_designer_spec.md` §15.1.

따라서 **다음 패턴은 도입 전에 "콘텐츠가 숨을 수 있는가"를 먼저 검증하고, 근거를 스펙에 남긴다:**

| 패턴 | 위험 |
|------|------|
| 탭 | 기본 탭 외의 콘텐츠가 `hidden`. 비어 있는 기본 탭이 나머지를 전부 가린다 |
| 아코디언 | 닫힌 패널 = `hidden` 콘텐츠 + 기본 열림 선택 → **탭과 동일한 실패 모드** |
| 캐러셀·슬라이더 | 첫 슬라이드 외 은폐 + 자동 넘김이 읽는 속도를 통제 + 접근성 비용. **가장 위험하다** |
| 스크롤 등장 애니메이션 | JS 실패·reduced-motion 시 콘텐츠가 영구 비표시될 수 있다 |
| "더 보기" 접기 | 게시물 수가 적을 때 순이익이 없다. 도입 시 접힌 개수를 명시할 것 |

세로 길이가 길어지는 문제는 **비파괴적 수단**(섹션 앵커·바로가기 링크)으로 푼다. 바로가기에 **활성/선택 하이라이트를 넣지 마라** — "선택됨"이 보이면 나머지는 "안 보임"으로 읽혀 탭 은유가 재발한다.

### 0.5 이미지·썸네일은 1급 시민이다

시각적 요소가 중요하다는 것이 사용자의 명시적 요구다. 링크형 게시물(영상 등)에 썸네일을 넣는다.

- **고정 종횡비 박스(16:9)로 CLS 를 0으로 만든다.** `aspect-ratio` + `width`/`height` 명시
- **썸네일이 없는 항목과 같은 목록에 섞여도 레이아웃이 무너지지 않아야 한다.** 이것이 썸네일 도입의 실질 쟁점이다 — 플레이스홀더를 쓸지, 레이아웃을 분기할지 판정하고 근거를 남겨라
- 썸네일이 제목을 대체하지 않는다. 제목·출처는 항상 텍스트로 존재한다(§3 신뢰성 규칙)
- 장식 이미지의 `alt` 는 빈 문자열. 제목이 인접해 있으면 썸네일은 장식이다
- 외부 호스트 직접 로드는 **조합원 IP 를 제3자에게 노출**한다. 서버 캐싱을 기본으로 한다

### 0.6 이미지 교체 — 무게를 줄이되 «읽혀야 하는 것» 을 먼저 지킨다 (2026-08-25 신설)

조합원은 **집회 현장 모바일 데이터**로 이 이미지를 받는다. 원본을 그대로 올리지 않는다.

1. **판독 대상을 먼저 정한다** — QR 코드, 시각, 전화번호처럼 **틀리면 안 되는 것**.
2. **줄인 뒤 그것이 여전히 읽히는지 확인한다.** QR 은 **디코딩해서** 확인한다(육안 아님).
3. 배경이 사진성 그러데이션이면 **PNG 를 고집하지 마라** — 압축이 안 된다.

> **실측(2026-08-25 · 출석체크 안내)**: 원본 2794×1566 **PNG 3.9MB**.
> 1920 폭 PNG 로 줄여도 **2.1MB**(배경 그러데이션 때문). **1600 폭 JPEG q92 = 361KB**,
> 그 상태에서 **QR 디코딩 성공**. 표시 폭이 `max-w-[480px]` 이라 1600 이면 3배수로 충분하다.

⚠ **더 줄이려고 품질을 낮추기 전에 «판독 대상이 살아 있는지» 부터 확인**하라.
⚠ **파일명을 바꿔 캐시를 끊는다**(`qr-guide.png` → `qr-guide-2.jpg`). 같은 이름으로 덮으면
이미 받은 조합원에게 **옛 이미지가 계속 보인다** — 시각이 바뀌었을 때 이것은 오정보다.
⚠ 원본은 `design/` 에 **알아볼 수 있는 이름**으로 보관한다(UUID 파일명 금지).

### 0.7 «우리 페이지 안 조작» 과 «밖으로 나가는 것» 은 형태로 가른다 (2026-08-25 명문화)

- **아웃라인/솔리드 필 버튼** = 우리 페이지 안에서 일어나는 조작
- **카드**(제목 + 설명 + `↗` + 도메인 표기) = **외부 이동**

⚠ 외부 링크를 필 버튼으로 만들지 마라. 강조가 필요하면 **버튼으로 바꾸지 말고 카드의 면을 채운다** —
형태는 «어디로 가는가» 를, 무게는 «얼마나 중요한가» 를 진다. 둘은 다른 축이다.
(선례: 출석체크 카드를 흰 면 → **남색 면 + 흰 글자**로 올리되 카드 형태는 유지. 대비 11.37 / 7.81.)

⚠ **지도·캔버스 위 컨트롤은 채운 면**이다. 배경이 매 프레임 바뀌는 곳에서 **테두리로 만든 경계는
배경에 따라 약해진다.** 반투명도 금지 — 대비를 보장할 수 없다.

### 0.8 텍스트 확대 200% — 처방은 «문자 종류» 가 가른다 (2026-08-26 신설)

2026-08-26 라운드에 **같은 결함을 네 번** 만났다: 캡션 `금융노조지부배치도` **32px 넘침** ·
산문 다리 문장 **110px 넘침** · 도메인 줄 **16px 넘침** · 상품권 조건 문장 **28px 넘침**.
매번 «그 문장 하나»를 재고 있었다. 자리와 문자 종류로 못박는다.

**처방 대응**(Tailwind 기준):

| 덩어리 | `break-keep` 단독 | 처방 |
|--------|-------------------|------|
| **한글** (`금융노조지부배치도` 9자 · 공백 0) | **넘침을 만든다** — 어절 유지가 통짜 덩어리를 만든다 | **`break-keep break-words`** |
| **라틴·도메인** (`docs.google.com` 15자) | **넘침을 못 막는다** — `keep-all` 은 CJK 규칙이라 라틴 낱말을 안 끊는다 | **`break-all`**(도메인 줄) 또는 `break-words` |

★ 같은 «공백 없는 덩어리»인데 **처방이 반대다.** 길이보다 **문자 종류를 먼저** 보라.
★ **`break-keep` 이 «없었으면» 안 넘쳤을 줄이 있다** — 낱말이 하나뿐인 캡션은 `break-keep` 이 막아 줄
«단어 중간 끊김» 대상이 아예 없는데 통짜 덩어리만 만든다. **처방이 문제를 만드는 경우다.**
⚠ **`break-all` 을 넓게 쓰지 마라** — 넘치지도 않는 `QR`·`LED`·`KDB` 같은 약어를 아무 데서나 끊는다.
약어가 뜻을 지는 문장에서 `Q/R` 로 갈리는 것은 미관 문제로 끝나지 않는다.
**한글 문장은 `break-keep break-words` 로, `break-all` 은 도메인·URL 줄로 한정한다.**

**판정선** (실측 · 360 뷰포트 · `html{font-size:32px}` · 스크롤바 15px · 한글 1자 ≈ 31.1px):

| 자리 | 200% 슬롯 | `break-keep` 단독 안전 한계 |
|------|----------|---------------------------|
| 패널 직속 (`p-5`) | 201px | **6자** |
| 카드 안 (`p-4`) | 137px | **4자** |

★ **한국어 종결어미가 이미 이 선에 걸린다**(`지급됩니다.` 6자 · `있습니다.` 5자)
→ **본문 문장은 사실상 전부 `break-words` 가 필요하다.** `break-keep` 만으로 통과 중인 문장은 우연히 짧은 것이다.
★ **`break-words` 는 달리 줄바꿈이 안 될 때만 발동해, 안 넘치는 줄에서 높이 변화가 0 이다**(실측).
**붙여서 손해 보는 줄이 없다.**
⚠ **한쪽에만 붙이지 마라** — «왜 여기만?» 의 답이 «지금 문면이 짧아서» 가 되는데 **그 근거는 문면에 매달린다.**
이번 라운드에만 한 캡션의 문면이 두 번 바뀌었다(**22자 → 3자**).

**눈대중 금지 — 두 방향으로 틀린다**(실측):

- **괄호에는 줄바꿈 기회가 있다** — `작성(지부천막)과` 는 폭 **242px** 인데 문장 min-content 는 **165px** 다
  (그 덩어리 «안»에서 끊긴다) → 공백으로 세면 **과대평가**
- **가운뎃점에는 없다** — `식대·교통비`(164.7px) = `식대교통비`(155.6px) + 점(9.1px). **6자 통짜다** → **과소평가**

> **공백으로 잘라 글자 수를 세지 마라. `width:0` 요소의 `scrollWidth` 가 유일한 참값이다.**

## 1. 타이포그래피 스케일

조합원 연령대가 넓으므로 일반 웹 기본값(16px)보다 큰 본문을 기준으로 한다.

| 토큰 | 크기 | 용도 | 굵기 |
|------|------|------|------|
| `text-display` | 40px / 2.5rem | 페이지 대제목 | 700 |
| `text-h1` | 32px / 2rem | 섹션 제목 | 700 |
| `text-h2` | 24px / 1.5rem | 소제목, 카드 제목 | 600 |
| `text-body` | 18px / 1.125rem | 본문 (기본) | 400 |
| `text-caption` | 15px / 0.9375rem | 보조 정보 (날짜, 출처) — 이보다 작은 텍스트 금지 | 400 |

- 본문 행간 1.7, 제목 행간 1.3. 본문 한 줄 최대 길이는 한글 기준 약 35~40자(`max-width: 42rem` 수준) — 긴 줄은 시선 복귀를 어렵게 한다.
- 위계는 크기+굵기로만 만들지 말고 간격으로도 만든다: 섹션 위 여백은 아래 여백의 2배 이상(소속이 명확해진다).
- 강조는 **크기 또는 굵기**로 한다. 이탤릭·밑줄 남용은 한글 가독성을 해친다 (밑줄은 링크 전용).

## 2. 색상과 대비

### 대비 기준 (필수 준수)

| 대상 | 최소 | 목표 |
|------|------|------|
| 본문 텍스트 | 4.5:1 (WCAG AA) | **7:1 (AAA)** |
| 큰 텍스트 (24px+ 또는 19px+ bold) | 3:1 | 4.5:1 |
| UI 컴포넌트 경계·아이콘 | 3:1 | 3:1 |

이유: 4.5:1은 정상 시력 기준이다. 고령·저시력 조합원까지 고려하면 본문은 7:1을 지향해야 안전하다.

### 대비 검사 스크립트

색 조합을 스펙에 확정하기 전에 반드시 실행한다:

```bash
node .claude/skills/union-design-system/scripts/check-contrast.mjs "#1a1a1a" "#ffffff"
# 출력: ratio 17.40 → AAA(본문) 통과
```

여러 조합을 한 번에 검사하려면 `전경색:배경색` 쌍을 나열한다:

```bash
node .claude/skills/union-design-system/scripts/check-contrast.mjs "#1d4ed8:#ffffff" "#374151:#f9fafb"
```

스펙 문서에는 검사 결과(비율 수치)를 표로 함께 기록한다. 검사하지 않은 색 조합을 스펙에 넣지 않는다.

### 팔레트 원칙

- **기본 팔레트(플레이스홀더)**: 텍스트 `#1a1a1a`, 배경 `#ffffff`, 주조색 파랑 계열 `#1d4ed8`(전국금융산업노동조합 계열의 관례적 색상군), 경고/긴급 `#b91c1c`. **실제 지부 CI(로고·공식 색상)가 확보되면 그 값으로 교체하고 대비를 재검사한다.** CI를 추측으로 단정하지 않는다.
- 색은 의미를 갖는다: 주조색=일반 강조/링크, 적색=긴급·마감·쟁의, 녹색=완료·타결. 한 페이지에 의미색 3종을 초과하지 않는다.
- **색만으로 의미를 전달하지 않는다.** 긴급 공지는 색 + 아이콘 + "긴급" 레이블을 병행한다 (색각이상 조합원 대응).
- 회색 텍스트를 "세련됨"의 수단으로 쓰지 않는다. 보조 정보라도 `#595959`(백색 배경 대비 7:1)보다 밝은 회색 금지.

## 3. 정보 위계 — 조합원의 행동 기준

페이지 내 정보의 시각적 우선순위는 "조합원이 해야 할 행동"을 기준으로 정한다:

1. **행동 필요 + 기한 있음** (투표, 신청 마감, 총회 참석) → 최상단 고정 배너 또는 강조 카드. 기한을 큰 텍스트로
2. **알아야 할 변화** (협약 타결, 제도 변경) → 메인 리스트 상단, 카드형
3. **일반 소식** (활동 보고, 행사 후기) → 일반 리스트
4. **상시 정보** (조직 소개, 규약, 연락처) → 내비게이션/푸터

모든 게시물에는 게시일과 출처를 caption으로 명시한다 — 정보 신뢰성의 시각적 표현이다.

## 5. 반응형·기타 원칙

- 분기점: 모바일 우선, `sm 640px / md 768px / lg 1024px`. 조합원 다수는 모바일로 접근한다고 가정한다.
- 터치 대상 최소 44×44px (버튼, 링크 간격).
- `:focus-visible` 스타일 필수 정의 (키보드 사용자용, 대비 3:1 이상의 아웃라인).
- 다크 모드는 초기 범위에서 제외한다 — 대비 검증 대상이 2배가 되므로, 라이트 모드의 완성도가 먼저다. 도입 시 모든 조합을 재검사한다.
