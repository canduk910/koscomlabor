# 보고서 — **지부 실무자가 읽는다**

읽는 사람은 개발자가 아니다. 코드를 열어 볼 사람도 아니다.
**「우리 페이지가 어떻게 달라졌나」**와 **「내가 뭘 정해야 하나」** 두 가지를 알려고 연다.

## 1. 말투

**「―합니다」 경어체다**(사용자 확정 2026-09-07). 「―한다」로 쓰지 마라.

## 2. 쉬운 말 — 이것이 이 보고서의 핵심 요구다

★ **기술 용어를 쓰지 않는 것이 목표가 아니다. «읽고 무슨 일인지 알게 하는 것»이 목표다.**
그래서 용어를 지우기보다 **우리말로 풀어 쓴다.** 꼭 필요하면 괄호로 원어를 남긴다.

| 쓰지 마라 | 이렇게 |
|---|---|
| ISR 캐시가 stale 상태로 서빙됨 | 화면을 미리 만들어 두고 보여주는데, **낡은 것이 먼저 나갔습니다** |
| 마이그레이션 적용 | 데이터베이스에 **새 표를 만들었습니다** |
| 엔드포인트 · 라우트 | **주소** (예: 「`/pledges` 주소」) |
| 배포 · 롤아웃 | **서버에 올렸습니다** |
| soft delete | **지운 표시만 하고 실제로는 남겨 둡니다** |
| 렌더 · 빌드 | **화면을 만드는 일** |
| 커밋 3건 · PR | 굳이 적지 마라. 사용자가 볼 것이 아니다 |

⛔ **영어 약어를 설명 없이 쓰지 마라.** `AAA`, `ISR`, `CD`, `API` 는 처음 나올 때 한 번 푼다.
   (`API` 는 「우리 서버」로 바꿔 쓰면 대부분 통한다.)
⛔ **파일 경로·함수명·클래스명을 본문에 늘어놓지 마라.** 그것은 코드 주석의 일이다.
   꼭 필요하면 맨 아래 「자세한 내용」 절에 몰아 둔다.

★ **문장을 짧게.** 한 문장에 뜻 하나. 접속사로 이어 붙이지 마라.
★ **개조식 단문 나열을 남발하지 마라.** 표는 값을 나열할 때 쓰고, 설명은 문장으로 쓴다.

## 3. 구성 — 이 순서다

```
① 한 줄 요약        지금 어떤 상태인가
② 무엇이 달라졌나    사용자가 화면에서 볼 수 있는 것 위주
③ 정해 주셔야 할 것  ★ 이 보고서의 목적
④ 지금 상태          공개/비공개, 남은 위험 같은 «사실»
⑤ 자세한 내용        (선택) 기술적 세부. 접어 두거나 맨 아래
```

⚠ **③ 이 없는 보고서는 만들지 마라.** 정할 것이 정말 없으면 그 절을 빼되,
   **「정할 것이 없습니다」를 한 줄로 밝힌다.** 빈칸은 «못 찾았다»로 읽힌다.

## 4. ③ 「정해 주셔야 할 것」 쓰는 법 — **여기가 전부다**

각 결정마다 **네 가지**를 갖춘다. 하나라도 빠지면 사용자가 되물어야 한다.

```
### 1. {물음을 «질문 문장»으로}

**무슨 상황인가**   왜 이 결정이 필요한지. 2~3문장.
**고를 수 있는 것**  선택지와 각각의 대가. 표가 좋다.
**제가 권하는 것**   ★ 하나를 고르고 이유를 댄다. 「알아서 하세요」 금지
**정하지 않으면**    지금 상태가 어떻게 유지되는지. 급한지 아닌지
```

★ **선택지의 «대가»를 반드시 적는다.** 「A 또는 B」만 주면 고를 수 없다.
   무엇을 얻고 무엇을 잃는지 나란히 둔다.
★ **급한 것과 안 급한 것을 갈라라.** 안 급하면 「급하지 않습니다」라고 적어 준다.
   전부 급해 보이면 사용자는 아무것도 못 정한다.

## 5. 숫자와 사실

- **확인한 것만 적는다.** 실측값·커밋·프로덕션 응답을 직접 본 것만.
- **못 확인한 것은 「확인하지 못했습니다」라고 적는다.** 비워 두지 마라 — 빈칸은 «없다»로 읽힌다.
- 숫자에는 **무엇을 잰 것인지**를 붙인다. 「43건」이 아니라 「공약 43건 중 23건 달성」.
- ⛔ **사실 판정을 하지 마라.** 공약이 실제로 달성됐는지는 사용자가 정한다(`CLAUDE.md`).
  우리는 「관리자 화면에 달성으로 기입돼 있습니다」까지만 쓴다.

## 6. 아티팩트로 낸다

- `Artifact` 도구로 발간하고 **URL 을 건넨다.** 대화창에 전문을 쏟아붓지 마라
- 발간 전에 **`artifact-design` 스킬을 읽는다**(그 스킬이 그렇게 요구한다)
- 제목은 **짧은 이름**이다. 예: `공약 대시보드 작업 보고` — 설명을 붙이지 마라
- 같은 대상의 보고서를 다시 낼 때는 **이전 아티팩트를 읽고 같은 URL 에 갱신**한다
  (`action: "list"` → `"read"` → 같은 `url` 로 재발간). 새 URL 을 만들면 링크가 둘이 된다

## 7. 하지 마라

- ⛔ **자화자찬.** 「완벽하게」·「깔끔하게」·「성공적으로」를 쓰지 마라. 값과 사실이 말하게 한다
- ⛔ **실패를 묻지 마라.** 못 한 것·놓친 것·미룬 것을 ②나 ③에 그대로 적는다
- ⛔ **분량으로 승부하지 마라.** 짧아도 ①~④가 있으면 좋은 보고서다
- ⛔ **사용자가 이미 아는 것을 되풀이하지 마라.** 대화에서 방금 확인한 것을 다시 설명하지 않는다
