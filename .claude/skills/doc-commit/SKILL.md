# 작업 후 기록·커밋

## 무엇을 남기나 — **「지금 사실」만**

| 성격 | 갈 곳 |
|---|---|
| **되돌리면 안 되는 이유** | **소스 주석** — 「하지 마라 + 왜」 한 줄 |
| **미룬 것** | `_workspace/FOLLOWUPS.md` |
| **다른 작업에도 걸리는 규칙** | 해당 스킬(`union-webapp-dev`·`union-qa-testing`·`union-design-system`) |
| **사용자·환경의 함정** | 메모리(`~/.claude/projects/…/memory/`) |

⛔ **판정 이력 문서·절 번호 체계·회차별 산출물을 새로 만들지 마라.**
⛔ **소스 주석에 있는 것을 문서로 복사하지 마라** — 두 벌이 되면 코드 고치는 사람은 주석만 고친다.

## 회수가 절반이다

- 해소된 `FOLLOWUPS` 항목은 **지우지 말고** `[해소 YYYY-MM-DD]` + 어떻게 해소됐는지 한 줄
- **낡은 근거를 남기지 마라.** 판정을 유지해도 **근거가 바뀌면 근거를 다시 쓴다**
- ★ **결론 문장까지 본다** — 근거만 갈고 결론을 남기면 다음 사람은 결론을 읽는다

## 커밋

**코드와 문서를 분리해 커밋한다.**

```
feat|fix(scope): 한 줄

무엇이 왜 바뀌었는지. 실측값이 있으면 값으로.
```

### ⛔ 커밋 «전»에 검산한다
```bash
git diff --cached --name-only     # 본문이 말하는 파일이 전부 여기 있는가
```
> 커밋 본문이 어떤 파일 변경을 주장했는데 **그 파일이 커밋에 없던** 사고가 있었다.
> 편집 스크립트가 죽었는데 뒤이은 `git commit` 이 **별도 명령이라 그대로 실행**됐다.
> → **편집 → 검산 → 커밋을 `&&` 로 잇는다.** 커밋 후 `git show --stat` 으로 본문과 대조한다.

**푸시는 사용자가 지시할 때.**
