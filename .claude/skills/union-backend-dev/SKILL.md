# Union Backend Dev — NCP 백엔드 구현 표준

전국금융산업노동조합 코스콤지부 공식페이지의 백엔드 표준. 이 프로젝트 백엔드의 특수성: (1) 프론트 API 계층과의 **계약 일치**가 최우선, (2) 조합원 대상 서비스로서 **개인정보 최소주의**, (3) 인프라는 **NCP(Naver Cloud Platform)**.

## 1. 계약 우선 (Contract-First)

프론트의 `src/lib/api/*.ts`가 API 계약의 단일 출처다. 구현 순서:

1. 프론트 API 계층의 타입·함수 시그니처를 읽는다
2. `_workspace/06_backend_api_spec.md`에 명세를 쓴다: 엔드포인트, 메서드, 요청/응답 JSON shape(필드명·타입·옵셔널 여부), 에러 응답 형식, 상태 코드
3. 명세를 리더에게 확인받은 후 구현한다
4. 응답 필드명은 프론트 타입과 **문자 단위로 일치**시킨다 (camelCase 통일). snake_case DB 컬럼은 API 경계에서 변환한다

이유: "각자 올바른데 연결하면 깨지는" 경계면 불일치가 이 프로젝트 QA가 잡아온 버그의 최다 유형이다. 명세 없이 구현하면 QA가 교차 검증할 기준도 없다.

## 2. 아키텍처 결정 절차

**미확정 사항은 추측으로 확정하지 않는다.** 첫 백엔드 작업 시작 시 다음을 선택지·트레이드오프와 함께 리더/사용자에게 확인받는다:

| 결정 항목 | 대표 선택지 (NCP) | 판단 기준 |
|----------|------------------|----------|
| 컴퓨팅 | Server(VM) / Cloud Functions / Container Registry+간단 컨테이너 | 방명록 수준 트래픽이면 소형 Server 1대 또는 Functions로 충분. NKS(쿠버네티스)는 과설계 |
| DB | Cloud DB for MySQL / Cloud DB for PostgreSQL / VM 내 직접 설치 | 관리형(Cloud DB)이 백업·보안 패치 부담이 적다. 소규모면 VM 내 설치도 가능하나 백업 계획 필수 |
| API 프레임워크 | Node.js(Express/Fastify/NestJS) 권장 | 프론트와 언어 통일 → 타입 공유 가능성, 팀 유지보수성 |
| 도메인/TLS | 서브도메인(api.*) + HTTPS 필수 | 평문 HTTP로 조합원 데이터를 받지 않는다 |

결정 결과는 `_workspace/06_backend_api_spec.md` 상단에 "아키텍처 결정" 절로 기록한다 (무엇을, 왜).

## 3. 보안·개인정보 원칙

조합원 대상 서비스이므로 다음은 협상 불가 기본선이다:

- **개인정보 최소 수집**: 방명록은 닉네임+본문이 기본. 실명·사번·연락처를 수집하려면 목적과 함께 리더 승인 필수. 수집 항목은 API 명세에 명시
- **입력 검증은 서버에서**: 길이 제한, 필수 필드, 형식 검증을 서버에서 수행한다 (프론트 검증은 UX일 뿐 보안이 아니다). 저장은 원문 그대로, 이스케이프는 출력(렌더) 계층 책임 — 프론트 렌더러가 raw HTML을 실행하지 않음을 전제로 하되 이중 방어로 서버에서도 스크립트 태그 포함 여부를 검사해 거부할 수 있다
- **스팸 방지**: 최소한 IP 기준 rate limit + 연속 등록 제한. 문제가 되면 단계적으로 강화 (허니팟 필드 → 관리자 승인제)
- **시크릿 관리**: 커밋 금지. 환경변수 + `.env.example`(키 이름만). NCP 접근 키는 최소 권한으로 발급
- **프로덕션 데이터 변경은 항상 대상을 특정한다**: `DELETE`/`UPDATE`에 WHERE 절 없이 실행 금지 (`DELETE FROM posts;` 같은 전체 삭제는 어떤 경우에도 불가). 스모크 테스트 정리는 생성 시 받은 id를 기록해 두었다가 `WHERE id IN (...)`로 지운다. 테이블이 지금 비어 있어 보여도 마찬가지다 — 같은 명령이 실제 공지가 쌓인 뒤 재사용되면 조합의 공지가 전부 사라진다. 대량 정리가 꼭 필요하면 리더에게 대상 건수를 먼저 보고하고 승인받는다
- **CORS**: 공식페이지 도메인만 허용. `*` 금지
- **삭제·신고 경로**: 사용자 생성 콘텐츠(방명록)에는 관리자 삭제 수단을 처음부터 만든다. 부적절 게시물 방치는 노조 공식 채널의 신뢰 문제가 된다

## 4. 코딩·운영 규칙

- TypeScript strict, 타입 우회 금지 (프론트와 동일 기준)
- 에러 응답 형식 통일: `{ error: { code: string, message: string } }` — 프론트가 분기할 수 있는 안정적 code 문자열 사용
- 로그에 개인정보(본문, 닉네임)를 남기지 않는다. 요청 ID·상태 코드 중심
- DB 스키마 변경은 마이그레이션 파일로 관리한다 (수동 콘솔 변경 금지 — 재현 불가)
- 배포 절차·NCP 리소스 구성은 `_workspace/07_backend_impl.md`에 재현 가능한 단계로 기록한다. 콘솔 수동 작업이 필요하면 단계별 가이드로 작성해 사용자가 수행할 수 있게 한다

## 5. QA 연계

구현 완료 시 qa-tester가 다음을 교차 검증할 수 있도록 준비한다:

- API 명세(06) ↔ 실제 응답: 로컬/스테이징에서 curl로 각 엔드포인트의 실제 응답 JSON을 캡처해 명세 옆에 병기
- API 명세 ↔ 프론트 `src/lib/api/*.ts` 타입: 필드 단위 대조표
- 인증·rate limit·입력 검증: 경계값 테스트 케이스 목록 (초과 길이, 필수 필드 누락, 스크립트 포함 본문)
